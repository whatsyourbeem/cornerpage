## 확정된 블록 순서 (Step 2 최종)

```
0. 상단 고정바
1. 히어로
2. 신뢰 스트립
3. 비포/애프터 (transformations)         ← 신규
3-1. 리뷰 (reviews)
3-2. 전문가 프로필 (professionals)        ← 신규
3-3. 철학 (philosophy)
4. 분위기(atmosphere) + 갤러리 + 시설 스펙(facility) ← facility 신규
5. 메뉴/서비스 (item_consult)
6. 위치/정보
7. 하단 고정 CTA바
8. 이용방법
9. FAQ
```

**`lead_emphasis`(사장님이 직접 고르는 최우선 어필 포인트: transformations/reviews/professionals/facility)에 따라 3~3-2 구간의 순서가 바뀐다.** facility가 선택된 경우에만 예외적으로 공간 클러스터(4번)에서 분리되어 최상단으로 이동한다. 상세 로직은 아직 미정 — 이 블록들 각각을 정의할 때 함께 확정한다.

**"나도 할 수 있을까"(초보자 배려) 불안은 별도 블록 없이 `professionals`의 필드 + FAQ 필수 문항으로 분산 처리한다.**

## 블록 0. 상단 고정바

### 층1 (슬롯 구조)
general과 동일. 신규 필드 없음.
```json
"topbar": {
  "display_name": "string, required",
  "action_button": { "type": "call | reservation | direction", "label": "string" }
}
```

### 층2 (작성 원칙)
- general 원칙(로고/가게명 배치, 메뉴 햄버거 넣지 않음 — 이탈 링크이자 집중 원칙 위반) 그대로 유지.
- **내비게이션 메뉴(섹션 앵커 이동)는 검토 후 최종적으로 넣지 않기로 결정.** 이유: (1) 스키마·질문지·evals 전반에 관리 표면적이 늘어나는데 비해 실익(스크롤 절감 정도)이 작음, (2) 이 vertical의 핵심 설계 철학인 "방문자가 증거를 정해진 순서로 지나가게 하는 선형적 설득 경로"와 충돌 — 네비게이션은 본질적으로 자유 점프를 허용하는 브라우징형 UX라 철학에 틈을 만듦.
- **`action_button.type` 기본값 = `reservation`.** general의 토르짐(헬스장) 예시에서 이미 "PT 상담 예약"을 `reservation` 타입 + 커스텀 라벨로 처리한 선례가 있음 — 새 타입을 만들 필요 없이, `type`은 기술적 동작만 담당하고 "상담"이라는 뉘앙스는 `label`이 담당.
- **`cta_interaction_mode` 기본값 = `guided`.** Step1의 "강매 불안" 특성상 대부분 실제 상담 창구는 카톡·DM 등 사람 응대. `functional`은 예외적인 경우만.
- **라벨은 항상 저부담 문구로 고정.** "무료상담 신청", "체험 문의하기" 등만 허용. **"지금 등록", "결제하기", "구매하기" 같은 즉시결제성 라벨은 금지** — 상단바에서부터 강매 인상을 주면 안 됨.

### 층2.5 (좋은/나쁜 예)
**좋은 예:** `{ "type": "reservation", "label": "무료상담 신청" }`
**나쁜 예:** `{ "type": "reservation", "label": "지금 바로 등록하기" }` — 상담도 안 받았는데 등록을 압박.

(디자인: `design-guide.md` 10-1절)

## 블록 1. 히어로

### 층1 (슬롯 구조)
general과 동일, 신규 필드 없음.
```json
"hero": {
  "badge": "string, required",
  "headline": "string, required",
  "tagline": "string, required",
  "background_image_url": "url | null",
  "cta": { "type": "call | reservation | direction", "label": "string" }
}
```

### 층2 (작성 원칙)
general 원칙(3초 안에 읽힘, 감정 형용사 금지, 구체적 장면) 그대로 유지하되, 이 vertical 특화 사항:

- **배지**: 지역 + **구체적 전문 분야**로. "헬스장" 같은 뭉뚱그린 표현 대신 "PT 전문 스튜디오", "필라테스 스튜디오", "요가 지도자 스튜디오"처럼 구체화 — `definition.md`의 "웜 트래픽" 특성상 방문자는 이미 어느 정도 관심이 있는 상태라, 모호한 업종명보다 구체적 전문성이 3초 안의 인지에 더 유리함.
- **헤드라인 — 이 vertical만의 추가 제약**: **아직 증거(비포애프터·리뷰)를 보여주기 전 단계이므로, 결과를 과장 약속하는 문구는 금지.** "확실한 변화를 만들어드립니다" 같은 문구는 최상급 표현 회피 원칙에도 걸리고, 뒤에 나올 증거 블록의 역할을 헤드라인이 미리 가로채는 셈이라 구조상으로도 어색함. 헤드라인은 **정체성·전문성의 구체적 사실**에 뿌리박는다(경력 연차, 전문 분야, 지도 방식 등) — "결과 약속"이 아니라 "이 사람/공간이 어떤 존재인지"까지만.
- **CTA**: 상단고정바와 동일 원칙 — `reservation` 타입, 저부담 라벨.

### 층2.5 (좋은/나쁜 예)
**좋은 예 (헤드라인):** "8년째 재활 전문으로, 한 사람만 보는 PT" — 사실(경력·전문분야·1:1 방식) 기반, 결과 약속 없음.
**나쁜 예:** "당신의 몸을 확실히 바꿔드립니다" — 증거 없이 결과부터 약속(최상급·과장 위험), 뒤에 나올 `transformations`·`reviews` 블록이 담당해야 할 역할을 가로챔.

(디자인: `design-guide.md` 10-2절)

## 블록 2. 신뢰 스트립

### 층1 (슬롯 구조)
general과 동일:
```json
"trust_strip": {
  "items": [ { "value": "string", "label": "string" } ]
}
```

### 층2 (작성 원칙)
general 원칙(지표 3개, 진실성, 데이터 없으면 대체)은 유지하되, **지표의 내용을 이 vertical 특화로 한정**:

- 우선순위: (1) 트레이너 경력 연차, (2) 누적 회원 변화 수 또는 보유 자격증 수, (3) 운영 연차 또는 상담 건수 중 데이터가 있는 것.
- **일반 헬스장식 지표(평수·기구 개수·24시간 운영 등)는 신뢰 스트립에 넣지 않는다** — 이 정보는 `facility` 블록의 몫. 신뢰 스트립은 "사람과 성과"에 집중, 시설 정보와 섞이면 `definition.md`의 "신뢰 근거 위계"가 흐려짐.
- 데이터가 부족하면(신생 스튜디오 등) `industry-data.md`의 대체 지표 후보를 참고(작성 예정).

### 층2.5 (좋은/나쁜 예)
**좋은 예:** "8년 · 지도 경력" / "127명 · 누적 변화 사례" / "4개 · 보유 자격증" — 사람·성과 중심.
**나쁜 예:** "500평 · 규모" / "24시간 · 운영" — 시설 지표가 신뢰 스트립에 섞임, `facility` 블록으로 이동해야 함.

(디자인: `design-guide.md` 10-3절)
